# База контактов

Локальное веб-приложение на Django для ведения корпоративных контактов. По умолчанию база хранится в SQLite (`db.sqlite3`). Для развёртывания можно подключить PostgreSQL через `DATABASE_URL`.

## Что умеет

- карточки контактов: ФИО, компания, отрасль, источник, должность, комментарий;
- отдельные e-mail и телефоны у контакта; адрес e-mail уникален в базе без учёта регистра, повторяющиеся телефоны разрешены;
- независимые отметки «Топ-менеджмент» и «GR»;
- поиск по ФИО, компании, должности, e-mail и телефону; фильтры по категории и отрасли;
- импорт CSV (UTF-8 / Windows-1251) и XLSX с предварительным просмотром; совпадения по e-mail можно обновлять или пропускать;
- импорт контактов и статусов из списка UniSender через API с предварительным просмотром;
- экспорт CSV и XLSX, по одной строке на каждый e-mail, с выбором выгрузки контактов без e-mail;
- журнал создания, изменения и удаления карточек;
- UniSender: отправка новых e-mail в выбранный список с double opt-in и обновление статуса подписки/доставки через webhook.

## Запуск на Windows

1. Установите Python 3.11 или новее.
2. Распакуйте проект в отдельную папку.
3. Откройте в ней командную строку и выполните:

   ```powershell
   py -m venv .venv
   .venv\Scripts\activate
   python -m pip install -r requirements.txt
   python manage.py migrate
   python manage.py createsuperuser
   python manage.py runserver
   ```

4. Откройте `http://127.0.0.1:8000/` и войдите созданной учётной записью.
5. В разделе `/admin/` можно добавлять отрасли и источники, а также просматривать историю изменений.

## Импорт

Первая строка файла — названия колонок. Поддерживаются заголовки на русском и английском: `Фамилия / Surname`, `Имя / First name`, `Отчество / Patronymic`, `Компания / Company`, `Отрасль / Industry`, `Источник / Source`, `Должность / Position`, `E-mail / Email`, `Телефоны / Phones`, `Топ-менеджмент / Top management`, `GR`, `Комментарий / Comments`. Несколько e-mail и телефонов в строке разделяйте точкой с запятой. Импорт сначала показывает строки и совпадения, затем предлагает обновить совпавшие карточки или пропустить их. Если e-mail строки указывает сразу на несколько существующих карточек, строка будет пропущена.

Для импорта из UniSender откройте раздел «Импорт» → «Импортировать из UniSender». CRM запросит API-выгрузку, затем нужно нажать «Проверить готовность и загрузить». После предварительного просмотра выберите, обновить ли карточки, совпавшие по e-mail, или пропустить их. Если задан `UNISENDER_LIST_ID`, загружается этот список; если он пустой — выгрузка запрашивается по всем спискам аккаунта. E-mail, телефоны, поля контакта и статус рассылки импортируются в CRM. Совпадения ищутся по e-mail, записи UniSender без соответствующей карточки создаются, а записи CRM не удаляются из-за отсутствия в выбранном списке. Размер скачиваемой выгрузки ограничен 25 МБ.

## UniSender

1. Создайте список контактов в UniSender и получите API-ключ. Проверьте, что в аккаунте существуют поля `Name`, `LastName`, `Company`, `Position`; если они называются иначе, задайте соответствующие переменные `UNISENDER_FIELD_*` в `.env`.
2. Скопируйте `.env.example` в `.env` и задайте `UNISENDER_API_KEY`, `UNISENDER_LIST_ID`, `UNISENDER_WEBHOOK_TOKEN`. API-ключ и ID списка берутся в аккаунте UniSender. `UNISENDER_WEBHOOK_TOKEN` — это ваш собственный секретный случайный токен, UniSender его не выдаёт. Например, сгенерируйте его командой `python -c "import secrets; print(secrets.token_urlsafe(32))"` и вставьте результат в `.env`.
3. Новые e-mail передаются в выбранный список через API `subscribe` с запросом подтверждения подписки (`double_optin=0`). Подтверждение и отписка приходят обратно в карточку через UniSender webhook.
4. Адрес обработчика: `https://ваш-домен/hooks/unisender/<значение-UNISENDER_WEBHOOK_TOKEN>/`. В настройках UniSender установите webhook с событиями `subscribe`, `unsubscribe` и `email_status`, формат `json_post_gzip` или `json_post`.

При локальном запуске браузер открывает CRM по адресу `http://127.0.0.1:8000/`, поэтому локальный адрес обработчика выглядит так: `http://127.0.0.1:8000/hooks/unisender/<ваш-токен>/`. UniSender не может обратиться к `127.0.0.1` на вашем компьютере. Для локальной проверки нужен HTTPS-туннель (например, ngrok или Cloudflare Tunnel), который перенаправляет запросы на порт 8000. Тогда в настройках webhook укажите выданный туннелем адрес, например `https://abc123.ngrok-free.app/hooks/unisender/<ваш-токен>/`, и добавьте `abc123.ngrok-free.app` в `DJANGO_ALLOWED_HOSTS` в `.env`. Домен временного туннеля может меняться; при смене обновите URL webhook и `DJANGO_ALLOWED_HOSTS`. Для постоянной работы разместите CRM на доступном сервере с HTTPS.

Отправка новых контактов отключена, если не заполнены API-ключ или список. Импорт из UniSender требует API-ключа; если ID списка пуст, экспорт запрашивается по всем спискам. Кнопка «Синхронизировать UniSender» повторно отправляет адреса, которые ещё не синхронизированы.

## Переключение на PostgreSQL

Создайте PostgreSQL базу и задайте переменную окружения `DATABASE_URL`, например `postgresql://user:password@localhost:5432/contacts_crm`. Зависимости для PostgreSQL уже указаны в `requirements.txt`. Выполните `python manage.py migrate` для пустой базы или подготовьте перенос SQLite → PostgreSQL отдельно перед запуском на рабочей базе.

## Перед публикацией в интернете

В `.env` установите `DJANGO_DEBUG=0`, длинный случайный `DJANGO_SECRET_KEY`, и перечислите домены в `DJANGO_ALLOWED_HOSTS`. Запускайте приложение через production WSGI/ASGI-сервер за HTTPS reverse proxy. Для нескольких сотрудников потребуется отдельная настройка ролей и резервного копирования.
